# ECHOPOST — Build Status

**Build label:** Foundation / early playable slice  
**Project engine:** Godot 4.x  
**Target:** Android first, desktop for development and QA

## Implemented in this source

- Standalone Godot project entry point; the supplied ECHO logo is used in the main menu, project icon and Android launcher, with a matching geometric SVG identity asset.
- Main menu, scrollable chapter select, scrollable Memory Archive, instructions, pause, completion, retry and continue flows. UI uses near-black navy surfaces, fine teal/cyan edges, restrained glow and a geometric tunnel backdrop to match the supplied ECHO logo. Player/echo markers now use a spherical neon signal orb with an orbit ring; recorded paths render as layered aura/halo/core lines; the playfield has subtle animated circuit-corner rails and a low-opacity signal sweep. The logo appears on full-height menus; compact layouts hide it before reflow and restore the full title/intro/button layout as the viewport grows. Regression coverage includes logo/project-icon path assertions, logo visibility/restoration, ten viewport sizes and non-overlapping gameplay controls.
- Keyboard movement and a floating, thumb-placed joystick on either side of the playfield. Touch pickup zones cover most of the configured side rather than only the corner; the top HUD, center gutter and bottom utility band are protected. A radial dead zone filters finger jitter, short drags remain proportional, long drags cap cleanly, and brief easing starts/stops touch movement without affecting immediate keyboard response. Gameplay actions now use translucent round glass controls: the large REC button sits on the right above bottom utility circles by default, the optional latch circle sits alongside it, and Pause/Menu/Restart use smaller round controls. Left-handed mode mirrors the action cluster to the left. The status banner and movement hint adapt so they do not overlap the control cluster.
- **Low-end rendering:** saved Performance Mode defaults ON (including older settings files). On mobile it targets 30 FPS, halves room-grid density, disables animated rails/scan sweep, lowers optional arc tessellation, simplifies the orb and joystick, and batches route traces into one polyline. Null Corridor's live jammer preview updates once per sampled segment rather than rescanning the entire route every frame. OFF restores full effects and a 60 FPS mobile cap. No physical low-end device benchmark has been completed yet.
- Options panel with slow/normal/fast movement presets and a left-handed joystick option; these preferences persist in a separate settings file, independent from campaign saves.
- Latch Protocol's toggle Switch B is functional: a dedicated on-screen button and keyboard E activate it only when the player is near B and the echo has finished playback and settled on A; the latched state remains active after leaving the switch and resets on room restart.
- Timestamped route recording with a strict 8-second cap (elapsed time is clamped before the final sample), echo playback, final-position linger, live amber route preview while recording, and rejection feedback when a route does not end on Switch A.
- Too-short recording feedback now tells the player to keep recording; the minimum-duration check and displayed 0.7-second requirement share one constant.
- Sentinel contact and required-relay failure now trigger automatic same-room restarts. A centered SIGNAL LOST / ROUTE FAILED card briefly explains the cause, blocks further input during the transition, displays a shrinking reset indicator, then restores a clean room state without requiring a manual restart. Relay-room endpoint misses also take this path.
- Echo track copies instantiate from their preloaded script resource instead of relying on a global `EchoTrack` class registration; this fixes the Godot 4.4 compile failure reported during local testing.
- Two-switch gate and portal completion flow.
- Seventeen authored room layouts across two chapters. Chapter I progresses from the two-switch tutorial through ordered relays, toggle/timed gates, the Dead Air Protocol sentinel gauntlet, and Null Corridor's 105-unit echo-only jammer. Chapter II adds **Glass Horizon** (three relays plus a sentinel sweep), **Clockbreak Crossing** (three relays plus a 2.8-second gate), **Switchback Protocol** (ordered relays, jammer bypass and latched Switch B), and **The Last Chorus** (four relays, jammer bypass, sentinel and 2.8-second gate).
- One optional Memory Shard and lore fragment per chamber, rendered as a glowing violet diamond; collection is tracked in menu progress and saved locally. The Memory Archive allows rereading recovered fragments and shows undiscovered rooms. Collecting all seventeen restores the courier network's final signal and displays the reward in-game and in the Archive. The archive's default count text uses the live room count rather than a hard-coded number.
- Level-catalog validation for unique/non-empty names, room bounds, minimum route distance, switch separation, and safe sentinel patrol height/width/speed; arbitrary draft arrays can be validated without editing the canonical campaign.
- Version-2 local campaign save data, Memory Shard collection persistence, validation of shard indices, and backward-compatible loading of version-1 saves.
- Separate settings store with default values and normalization to supported movement presets; Options UI/handedness integration tests are green on both supported CI Godot versions.
- Automatic pause on Android/iOS application suspension or application focus loss; held joystick input is cleared, in-progress recording state is preserved, and gameplay never auto-resumes without player input.
- Static Bloom Relay Beacon: its echo recording must pass within the beacon radius and finish on Switch A; segment-distance checking correctly counts crossings between recorded sample points.
- Chorus Route ordered Relay Beacons: the echo recording must cross Relay 1 before Relay 2 and then finish on Switch A. Reversed relay order is rejected; linked/unlinked beacon visuals reflect the encounter order, and waypoint lists are validated for type, bounds, and safe separation.
- Pulse Lock timed gate: both switches open a 3.5-second crossing window. The countdown ticks only while gameplay runs, timeout closes the gate if the player is still before the barrier, leaving either switch rearms a retry, and crossing safely keeps the portal powered. The playfield and HUD display the remaining window, including a shrinking amber progress bar that starts full and empties at timeout.
- Campaign-data validator and smoke tests including intentionally malformed room drafts, unique room names, seventeen-room data, three-/four-relay sequences, relay/timed-gate combination and sentinel gauntlet, Memory Shard/lore and relay/timed-gate data/bounds, version-2 shard save round-trip and version-1 compatibility, isolated control-preference save/normalization, normal and all-shards-restored pickup/persistence, dynamic Archive count text, echo-track copy identity, exact eight-second cap, too-short feedback, sentinel interruption, restart cleanup including toggle-latch reset, toggle-button/keyboard E validation, portal completion idempotency, scrollable chapter/archive/options UI, responsive HUD/modal anchoring, larger mobile touch targets, direct route rejection, valid relay-segment acceptance, ordered relay sequence and linked-state validation, timed-gate countdown label/bar ratio/timeout/retry/crossing, automatic room-reset countdown/cleanup after sentinel and relay failure, gate activation Null Corridor jammer rejection/reset and safe bypass, and lifecycle pause/resume.
- Automated GitHub Actions workflow that imports/parses the project and runs both smoke-test scripts.
- Tracked Android arm64 export preset and GitHub Actions workflow that exports and ZIP-validates a debug APK, uploads the build artifact, and publishes a nightly GitHub Release.
- README, design document, roadmap, contribution guide, and MIT license.
